# Synthetic ICU Data Hallucination & Quality Evaluation Pipeline

Evaluation pipeline for assessing hallucination rates and data quality in
synthetic ICU patient data generated by four generative models (CTGAN, ARF,
RTVAE, DDPM), benchmarked against a MIMIC-III-derived reference population.
Developed as part of a PhD thesis on synthetic data validation for AI in
healthcare.

Each generator is evaluated in two variants: a "full" dataset (23 variables)
and a "core" dataset (13 variables). Internally these are referred to by
their raw folder prefixes, `Step7pfa` (full) and `Step7pfp` (core).

## Repository structure
config/ Shared configuration
pipeline_config.py Paths, per-generator settings, LLM cost/model config
clinical_ranges.py Physiological reference ranges and rule parameters
expert_rules.py 36 clinical plausibility rules (impossible / suspicious)

hallucination_pipeline/ Steps 0-4 of the hallucination evaluation
step0_make_readable.py Prepares raw synthetic output for downstream steps
step1_hr_pilgram.py Pilgram HR / HR_adjusted / exact-copy-rate
step2_expert_rules.py Applies the expert rule set, flags impossible/suspicious rows
step3_llm_evaluator.py LLM-based coherence review of expert-unflagged rows (Claude API)
step3b_merge_llmresults.py Merges Step 3 results into the shared summary files
step4_per_chain_summary.py Reshapes Steps 1-3 output into per-chain tables

extract_qa_metrics/ TSTR/TRTR and synthetic-data-quality metric extraction

visualization/ Figure generation (trajectories, frequency pages, tables)

statistics/ Hypothesis tests and manuscript/appendix tables

summary_files/ Pipeline output (generated, not tracked in this repo)


## Requirements

Python dependencies are managed with [uv](https://docs.astral.sh/uv/).

```bash
uv sync
```

Step 3 additionally requires an Anthropic API key. Create a `.env` file in
the repo root (never committed):
ANTHROPIC_API_KEY=your-key-here

## Data

This repository contains no patient data. The reference population is
derived from MIMIC-III and is subject to the PhysioNet Data Use Agreement;
it must be obtained independently via credentialed PhysioNet access and is
never distributed alongside this code. Synthetic data generation itself is
out of scope for this repository — the pipeline here evaluates
already-generated synthetic CSVs, expected under `Data/SD_evaluationready/`
in the layout `config/pipeline_config.py` documents.

## Running the pipeline

Steps 1, 2, and 4 run automatically for all four generators via the
orchestrator:

```bash
python hallucination_pipeline/run_pipeline.py                 # full (pfa) variants
python hallucination_pipeline/run_pipeline.py --variants core  # core (pfp) variants
python hallucination_pipeline/run_pipeline.py --variants both
python hallucination_pipeline/run_pipeline.py --steps 2        # a single step
python hallucination_pipeline/run_pipeline.py --dry-run        # show the plan only
```

**Step 3 is run manually, one generator at a time**, since it makes billable
Claude API calls:

```bash
python hallucination_pipeline/step3_llm_evaluator.py
python hallucination_pipeline/step3b_merge_llmresults.py
```

Set `GENERATOR` in `config/pipeline_config.py` before running Step 3, and
keep an eye on `MAX_SPEND_USD` in the same file. Progress is checkpointed,
so an interrupted run resumes without repeating completed files or
re-billing completed batches.

## Outputs

All pipeline output is written under `summary_files/`, organized by stage
(`hallucination_pipeline/`, `per_chain_summaries/`, `results/` for
print-ready tables and figures). See the module docstring in each script
for exact output paths.
